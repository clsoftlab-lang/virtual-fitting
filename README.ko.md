# 👗 가상 피팅 룸 · Virtual Fitting Room

온라인 의류 구매의 **사이즈/핏 오류**를 줄이는 브라우저 전용 **가상 피팅** SPA.
신체정보(키/몸무게/성별/체형)를 입력하면 아바타로 미리 입어보고, **설명 가능한 규칙 기반
사이즈 추천**과 부위별 핏 배지(**타이트 / 적당 / 넉넉**), 스케일링된 SVG 아바타 미리보기를 제공합니다.
머신러닝·3D 스캔·빌드 과정이 전혀 없습니다.

**🔗 라이브 데모: https://clsoftlab-lang.github.io/virtual-fitting/**

> English: **[README.md](README.md)**

## 왜 만들었나

패션 이커머스 반품의 가장 큰 원인은 사이즈/핏 불일치입니다. 이 프로젝트는 *내 치수*를
*각 의류의 사이즈표*와 비교해, 부위별로 타이트/적당/넉넉을 **수식이 그대로 보이는 방식**으로
알려주는 투명한 기하 엔진을 보여줍니다.

## 기능

- **신체 프로파일** — 키/몸무게/성별/체형 → 신체 둘레(가슴·허리·엉덩이·어깨·허벅지) + BMI 추정. 프리셋 제공.
- **스케일링 아바타** — 추정 치수에 비례해 실루엣이 변하는 인라인 SVG.
- **의류 카탈로그** — 상의/하의/아우터/원피스 34개(가상), 각 상품에 cm 사이즈표. 카테고리·성별·사이즈·검색·"잘 맞는 것만" 필터.
- **핏 엔진** — 사이즈·부위별 **여유(ease)** = 의류−신체 를 권장 여유 밴드와 비교 → **추천 사이즈** + 핏 배지 + 0~100 핏 점수.
- **착장 미리보기** — 아바타 위에 의류를 얹어 핏(초록/빨강/파랑)으로 색칠, 기장은 실제 사이즈표 값에 연동.
- **비교** — 최대 4개 상품 나란히 비교(추천 사이즈·배지·점수·부위별).
- **찜 / 장바구니(모의)** — `localStorage` 저장, 초기화 지원.
- **사이즈표 vs 내 치수** 매핑 표(칸마다 부호 있는 여유 표시).
- **라이트/다크** 테마, **모바일 우선 반응형**, 한글 UI.

## 핏 엔진 동작 원리 (수식)

모든 로직은 [`fit-engine.js`](fit-engine.js) 에 있으며 [`check.mjs`](check.mjs) 에서 단위 테스트됩니다.

**1. 신체 둘레 추정** — 부위별:

```
부위_cm = A[성별] · 키_cm + B · (몸무게 − 이상체중) + typeAdj[체형]
이상체중 = 22 · (키_m)²          // BMI 22 기준
```

- `A[성별]` — 키 비례 계수(남/여, unisex=평균)
- `B` — 이상체중 대비 편차 1kg당 둘레 증가
- `typeAdj` — 체형 보정(마른형/표준/운동형/굴곡형/통통형)

예 — 남성 175cm, 70kg, 표준: 이상체중 = 22·1.75² = 67.4kg, ΔW = +2.6kg →
가슴 = 0.514·175 + 0.60·2.6 + 0 = **91.5cm**.

**2. 사이즈·부위별 여유 계산:**

```
ease = 의류 실측 − 신체 추정      // cm
```

**3. 권장 여유 밴드 `[min, max]` 와 비교** (카테고리·부위별, 예: 셔츠 가슴 **+6~+16cm** 권장):

```
ease < min → 타이트   |   min ≤ ease ≤ max → 적당   |   ease > max → 넉넉
```

**4. 추천 사이즈** = 가중 penalty(밴드 이탈량, 부위 가중치—가슴/허리 우세)가 최소인 사이즈.
동점이면 '적당' 부위가 많은 쪽 → 작은 사이즈. 전체 배지는 카테고리 대표 부위(상의/원피스=가슴,
하의=허리)를 따르고, 핏 점수 = `max(0, 100 − 4·penalty)`.

## 로컬 실행

의존성·빌드 없음. ES 모듈과 `fetch` 때문에 `file://` 이 아닌 `http://` 로 서빙해야 합니다:

```bash
python -m http.server 8974
# http://localhost:8974 접속
```

검증 + 엔진 단위 테스트:

```bash
node check.mjs   # JSON 파싱 + 전체 JS node --check + index.html 요소 + 엔진 테스트
```

```
.github/workflows/ci.yml
```

## 데모 모드 한계

> **이 프로젝트는 데모입니다. 아래 경계를 확인하세요:**
>
> - **사이즈 산정은 규칙 기반 기하이며 3D/ML 신체 스캔이 아닙니다.** 신체 둘레는 키/몸무게/성별/체형에서 문서화된 선형 계수로 *추정*한 근사값입니다.
> - **아바타는 스케일링된 인라인 SVG 실루엣**이며 사실적/물리 시뮬레이션 드레이프가 아닙니다.
> - **모든 의류·브랜드·가격·사이즈표는 가상 시드 데이터**(`data/*.json`)입니다.
> - **실계정·결제·개인정보(PII) 없음.** 프로파일/찜/비교는 브라우저 `localStorage` 에만 저장되고 언제든 초기화됩니다.
> - **실서비스 확장 시** 사진 기반 광학측정(photogrammetry)/ML 신체추정, 실제 옷감 드레이프 시뮬레이션, 라이브 상품/재고 API, 브랜드별 반품률 학습을 붙일 수 있습니다.

## 🤖 AI 기능 (API 연동)

앱에는 **플러그블 AI 레이어**가 포함되어 세 가지 기능을 제공합니다.

1. **AI 스타일·핏 상담 챗봇** — 신체정보와 취향을 입력하면 핏 엔진 계산(부위별 여유·핏 점수)을 근거로 상품과 사이즈를 추천합니다.
2. **핏 결과 자연어 설명** — 추천 사이즈와 부위별 여유를 자연스러운 문장으로 설명합니다("가슴 +14.5cm 적당, 허리 타이트 → 한 치수 업").
3. **상황별 코디 추천** — 출근/데이트/운동/주말/포멀 상황별로 상·하의(또는 원피스)+아우터 코디를 제안합니다.

**데모는 별도 설정 없이 브라우저 내장 결정론적 한글 mock**(`ai/ai.js`)으로 바로 동작합니다. mock 은 앱의 카탈로그 데이터와 `fit-engine.js` 를 그대로 재사용하며, 키·네트워크·빌드가 필요 없습니다.

**실제 Claude 연동** 방법:

1. `server/`(얇은 프록시)를 `ANTHROPIC_API_KEY` 와 함께 배포합니다(비용 우선 기본 모델 `claude-haiku-4-5`, `AI_MODEL` 로 상향):
   ```bash
   cd server && cp .env.example .env   # .env 에 실제 키 입력
   npm install && npm start            # http://localhost:8787
   ```
2. `ai/config.js` 의 `AI_ENDPOINT` 를 그 주소로 설정합니다:
   ```js
   export const AI_ENDPOINT = "http://localhost:8787/api/ai"; // 또는 배포 도메인
   ```

브라우저는 프록시로 `{task, payload}` 만 보내고, 프록시가 키를 쥔 채 Claude 응답을 스트리밍으로 되돌려줍니다.

> **API 키는 서버 전용입니다 — 브라우저나 저장소에 절대 넣지 마세요.** `ai/config.js` 에는 키가 없고, `server/.env` 는 git 에서 제외되며, `check.mjs` 는 매 실행마다 커밋된 키를 스캔합니다.

## ⚙️ 고도화 — 무인·저비용 실 AI 연동

AI 레이어는 **저비용 · 무인 · 상시 동작**에 맞춰 조정되어 있습니다.

- **비용 우선 모델.** 기본 `claude-haiku-4-5` (약 **$1 / $5 per MTok** 입력/출력). 품질이 필요하면 `AI_MODEL=claude-sonnet-5` 또는 `claude-opus-5` 로 상향.
- **프롬프트 캐싱.** 태스크별 안정적인 시스템 프롬프트를 캐시 블록(`cache_control: ephemeral`)으로 전송해, 반복 호출은 캐시를 읽어 비용이 낮아집니다.
- **출력 상한 + 가드레일.** 태스크별 modest `max_tokens`(~700), IP당 레이트리밋(`AI_RATE_LIMIT_PER_MIN`, 기본 20/분), 월 토큰 예산(`AI_MONTHLY_TOKEN_CAP`, 기본 2,000,000). 한도 초과 시 프록시가 `429 {"fallback":true}` 반환.
- **대략 비용.** 그라운딩 1회 ≈ 입력 ~1.5k + 출력 ~0.4k 토큰 ≈ Haiku 기준 **~$0.0035**. 즉 **1,000 요청당 ~$3–4**(캐시 적중 시 더 저렴). 기본 월 상한은 취미 예산 안에 드는 하드 실링입니다.
- **무료 원클릭 배포(Cloudflare Workers).** `server/worker.js` + `server/wrangler.toml` 가 동일한 태스크 라우팅/모델/캐싱 규칙으로 Anthropic REST 를 호출합니다 — 무료 티어, 관리 서버 없음. `wrangler deploy` + `wrangler secret put ANTHROPIC_API_KEY`.
- **무인 · 절대 안 멈춤.** 신체정보 로드 시 앱이 fit-engine + `askAI` 로 **"내 체형 맞춤 추천 착장 Top 3"** 를 자동 생성합니다. 엔드포인트가 죽거나·예산 초과·`429 {fallback:true}` 면 `ai/ai.js` 가 **내장 mock 으로 자동 폴백**하여, 오프라인에서도 앱이 계속 동작합니다(무인).

> **API 키는 서버 전용입니다 — 브라우저나 저장소에 절대 넣지 마세요.** Worker 는 `ANTHROPIC_API_KEY` 시크릿에서만 키를 읽습니다.

## 반품률 절감 근거

패션 이커머스 반품 1위 사유가 사이즈/핏입니다. 구매 전 *부위별* 여유(예: "허리 타이트, 가슴 적당 → 한 치수 업")를
보여주면 소비자가 스스로 맞는 사이즈를 고르게 되고, 이것이 핏 기반 반품을 줄이는 핵심 레버입니다.
이 데모는 그 판단을 블랙박스가 아니라 투명하게 설명합니다.
